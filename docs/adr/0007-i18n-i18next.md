# 0007. i18next for internationalisation

- Status: Accepted
- Date: 2026-10-23

## Context

French and English from day one. Mods must be able to add or override translations at runtime.
Events and score breakdowns are produced by the core and must not carry formatted text.

## Decision

- **i18next + react-i18next**, with JSON resources loaded at runtime (mods can add or override keys).
- The core emits **translation keys and parameters** only (`{ key: "event.chapterPublished", params: { chapter: 12, rating: 7.8 } }`).
- Content never contains display text. Keys derive from content ids (`theme.adventure.name`).
- Plurals use `Intl.PluralRules`; numbers, money and dates go through `Intl`.
- Typed keys, so a missing key is a compile error.
- A CI test checks that `fr` and `en` expose exactly the same keys.
- The chosen pixel font must cover French characters (é, è, à, ç, œ, ...).

## Alternatives considered

- **Lingui.** Compile-time extraction is elegant, but compiled catalogs do not fit runtime mod overrides.
- **Custom minimal translator.** Plurals, interpolation and fallback languages are easy to get subtly wrong.

## Consequences

- No visible string is hard-coded in components (`AGENTS.md` 9.3).
- Saves never contain translated text, so language can change at any time.
- Every new feature ships with both locales.
